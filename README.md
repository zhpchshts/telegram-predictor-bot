<h1 align="center">Клевер</h1>

<p align="center">
  Telegram-бот и Mini App для конкурсов прогнозов на спортивные и
  киберспортивные турниры в групповых чатах.
</p>

«Клевер» позволяет участникам одного Telegram-чата создавать конкурсы,
прогнозировать результаты матчей и серий, следить за рейтингом и сравнивать
закрытые прогнозы. Основной интерфейс работает внутри Telegram Mini App.

Для новых конкурсов доступен шаблон Лиги чемпионов 2026/27. Завершённые
конкурсы Чемпионата мира по футболу 2026 и The International 2026
сохраняются в приложении вместе с результатами, рейтингами и историей
прогнозов.

## Возможности

- несколько активных и завершённых конкурсов в одном Telegram-чате;
- общие турниры с единым составом, расписанием, дедлайнами и результатами для
  нескольких чатов при раздельных прогнозах, рейтингах и Telegram-публикациях;
- прогноз счёта футбольного матча строго после 90 минут с автосохранением до
  времени начала;
- отдельный прогноз победителя или команды, которая пройдёт дальше;
- прогноз счёта киберспортивной серии по её официальному формату;
- двухматчевые футбольные противостояния: два независимых прогноза счёта
  после 90 минут и отдельный прогноз на проход до начала первой игры;
- сетка Лиги чемпионов из стыков, 1/8, 1/4, 1/2 и одиночного финала с
  автоматическим появлением пар в связанных конкурсах;
- опциональная синхронизация расписания и результатов плей-офф общего турнира
  через football-data.org с ручным повторным запуском из Mini App;
- долгосрочные прогнозы на чемпиона и итоги швейцарского этапа;
- составной прогноз общего этапа Лиги чемпионов без отдельных матчей:
  для каждой команды в интерфейсе доступны варианты «Напрямую», «Стыки» и
  «Вылет»; «Стыки» выбраны по умолчанию, а сохраняются до 8 команд, выходящих
  напрямую в 1/8 финала, и до 12 вылетающих;
- частичный выбор сохраняется как черновик, а полностью заполненный прогноз
  содержит ровно `8 + 12` команд и считается одним долгосрочным прогнозом;
- при подсчёте учитываются только прямой выход и вылет: за точно угаданный
  прямой выход начисляется 2 балла, за точно угаданный вылет — 1 балл;
  за стыки и ошибки — 0, максимум составляет 28 баллов;
- автоматическое начисление баллов и детерминированные тай-брейкеры;
- рейтинг, история закрытых прогнозов и журнал действий;
- публикация прогнозов, результатов и итогов конкурса в Telegram;
- управление супермодераторами на уровне чата.

Шаблон Лиги чемпионов не создаёт отдельные матчи общего этапа. Для плей-офф он
показывает каноническую сетку из 23 позиций: 8 стыков, 8 пар 1/8,
4 четвертьфинала, 2 полуфинала и финал. В общем турнире автоматическую загрузку
можно включить отдельно; найденные пары и результаты распространяются во все
связанные чаты. Независимые конкурсы и ручная коррекция общего турнира сохраняют
возможность добавить пару с явным раундом вручную.

Во всех футбольных матчах, включая одиночный финал, прогнозируется и учитывается
счёт строго после 90 минут. Дополнительное время и пенальти определяют только
победителя или прошедшую команду и не меняют счёт матча.

## Как открыть

1. Добавьте [@ZhpchshtsPredictorBot](https://t.me/ZhpchshtsPredictorBot) в
   групповой Telegram-чат.
2. Отправьте в чате команду `/app`.
3. Нажмите кнопку «Открыть Клевер» и выберите конкурс. Создание нового конкурса
   становится доступно, когда в приложении есть актуальный шаблон турнира.

Контекст конкурса привязан к чату, поэтому полноценное управление через личные
сообщения или отдельный набор команд не предусмотрено.

## Стек и устройство

- Python 3.14, FastAPI и aiogram;
- SQLite;
- HTML, CSS и JavaScript без отдельного frontend build pipeline;
- Docker Compose;
- один процесс приложения запускает API, Telegram polling и фоновые воркеры.

Основные каталоги:

- `app/` — API, бот, бизнес-логика, база данных, начисление баллов и публикации;
- `tma/` — интерфейс Telegram Mini App;
- `tests/` — автоматические тесты;
- `scripts/` — служебные миграции и операции обслуживания.

Подробные продуктовые правила и ограничения для разработки описаны в
[`AGENTS.md`](AGENTS.md), а канонические публичные тексты и визуальные принципы
— в [`docs/branding.md`](docs/branding.md).

## Локальный запуск

Понадобятся Python 3.14 и Telegram-бот, созданный через BotFather.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните как минимум `BOT_TOKEN` и `BOT_USERNAME` в `.env`. Для опциональной
автоматической синхронизации плей-офф Лиги чемпионов также задайте
`FOOTBALL_DATA_API_TOKEN`. Значение `CHAMPIONS_LEAGUE_SYNC_SEASON=2026`
означает сезон 2026/27 и является единственным допустимым для фиксированного
шаблона `champions_league_2026_27`; приложение завершит запуск с ошибкой при
другом значении, не смешивая сезоны. `CHAMPIONS_LEAGUE_SYNC_INTERVAL_MINUTES`
задаёт период фоновой проверки. Без токена воркер остаётся включённым, но
ничего не загружает. Саму синхронизацию администратор отдельно включает для
нужного общего турнира в Mini App.

Затем запустите:

```powershell
python -m app.main
```

Проверка состояния будет доступна по адресу
`http://127.0.0.1:8000/health`. Endpoint поддерживает методы `GET` и `HEAD`,
поэтому его можно использовать для внешнего мониторинга, в том числе
UptimeRobot. Оба метода проверяют доступность актуальной схемы БД и работу
Telegram polling, lifecycle worker, обоих publication workers и воркер
синхронизации Лиги чемпионов; при ошибке возвращается HTTP 503, а ответ на
`HEAD` не содержит тела. Для запуска Mini App внутри Telegram публичный
HTTPS-адрес приложения должен быть настроен для бота через BotFather.

Проверка администраторов Telegram при открытии Mini App ограничена коротким
таймаутом: недоступность Bot API не блокирует участникам просмотр конкурсов и
сохранение прогнозов, но операции, требующие актуального подтверждения статуса
Telegram-администратора, остаются недоступны до успешной проверки. Действующее
локальное назначение супермодератора при этом сохраняется. Дополнительные адреса
Bot API можно задать через
`TELEGRAM_BOT_API_FALLBACK_IPS`: DNS-адреса остаются первыми, а резервные IP
используются как дополнительные кандидаты при установке TCP-соединения без
повторной отправки API-запроса.

Альтернативный запуск через Docker:

```powershell
docker compose up --build
```

## Данные и production

Проект работает в production. База SQLite, Telegram MTProto session и секреты
не должны попадать в Git или диагностические артефакты.

`initialize_database()` создаёт актуальную схему для новой базы, но не является
универсальным механизмом обновления исторических схем. Перед изменением схемы
или логики начисления баллов необходимо проверить совместимость с существующими
конкурсами, матчами, результатами и прогнозами.

Единое правило футбольного счёта после 90 минут не меняет формат хранения:
в SQLite уже записываются только два числовых значения счёта без признака
продолжительности матча. Поэтому отдельная миграция или автоматическое
преобразование данных не нужны. Исторические прогнозы, результаты и начисленные
баллы остаются без изменений; новое правило применяется к новым или явно
изменяемым футбольным прогнозам и результатам.

Перед деплоем версии с шаблоном Лиги чемпионов 2026/27 на существующую
базу обязательно остановите приложение, создайте резервную копию SQLite и
запустите ручную миграцию:

```powershell
python -m scripts.migrate_champions_league_2026_27_schema data/predictor.db
```

Скрипт расширяет `CHECK`-ограничения `template_key` для конкурсов и общих
турниров, проверяет целостность БД и не заменяет резервную копию. Если в базе
осталась промежуточная настройка двух хранимых крайних категорий Лиги
чемпионов `8 + 16`, скрипт атомарно заменит её на `8 + 12` только при
отсутствии прогнозов и результата; 16 участников стыков затем вычисляются
как оставшиеся команды. При наличии таких данных, неполной связанной схеме
или отсутствующих настройках
миграция остановится без изменений для ручного разбора. Новую версию можно
запускать только после успешного завершения миграции.

Перед запуском версии с поддержкой двухматчевых противостояний на существующей
базе также остановите приложение и выполните отдельную миграцию:

```powershell
python -m scripts.migrate_two_legged_ties data/predictor.db
```

Скрипт сам создаёт резервную копию рядом с базой, добавляет универсальные связи
пары и двух матчей для локальных и общих турниров, а затем выполняет
`integrity_check` и `foreign_key_check`. Частично обновлённую или неожиданную
схему он не изменяет; такую базу нужно сначала разобрать вручную. Миграцию
запускайте после всех более ранних миграций схемы и до старта новой версии
приложения.

Перед запуском версии с частичными прогнозами общего этапа и формулой
`2 × прямой выход + 1 × вылет` остановите приложение и выполните:

```powershell
python -m scripts.migrate_general_stage_prediction data/predictor.db
```

Скрипт автоматически создаёт SQLite-бэкап рядом с базой, добавляет настройки
режима выбора и формулы в локальные и общие турниры, а затем переводит конкурсы
Лиги чемпионов на `up_to_limits / 2 / 1 / 0`. Он проверяет 36 команд, лимиты
`8 + 12`, частичные прогнозы, точные фактические результаты, связанные
настройки, `integrity_check` и `foreign_key_check`. Неоднозначную схему или
старые лимиты `8 + 16` с данными скрипт оставляет без изменений и завершает
ошибкой. Миграцию запускайте после более ранних миграций Лиги чемпионов и общих
турниров, но до старта приложения.

Управление общими турнирами показывается только Telegram-пользователям из
`SHARED_TOURNAMENT_ADMIN_IDS` (положительные ID через запятую). Это отдельный
глобальный доступ: права администратора конкретного чата его не дают. Связанный
конкурс получает общие команды, матчи, дедлайны, результаты матчей, чемпиона и
итоги швейцарского или общего этапа. Один общий турнир Лиги чемпионов можно
связать с конкурсами нескольких чатов; при этом пользовательские прогнозы,
рейтинги и Telegram-публикации остаются раздельными для каждого конкурса и чата.

Перед первым включением общих турниров на существующей базе сначала остановите
приложение и выполните анализ без изменений:

```powershell
python -m scripts.migrate_shared_tournaments data/predictor.db
```

Анализ переносит только активные конкурсы и считает одну пару команд одним
матчем независимо от времени. Он останавливается при неоднозначных составах,
результатах или форматах серий. Уже наступившие локальные дедлайны сохраняются,
не переоткрывая прогнозы; для ещё не наступивших расходящихся дедлайнов по
умолчанию выбирается самое позднее время. После устранения конфликтов примените
миграцию:

```powershell
python -m scripts.migrate_shared_tournaments data/predictor.db `
  --apply --actor-telegram-user-id 123456789 --time-policy latest
```

Перед записью скрипт автоматически создаёт SQLite-бэкап рядом с базой. Он не
отправляет заново исторические Telegram-публикации. После переноса проверьте
`PRAGMA foreign_key_check`, запустите тесты и только затем запускайте новую
версию приложения.

Перед запуском версии с сеткой и синхронизацией плей-офф Лиги чемпионов на
существующей базе после всех перечисленных выше миграций выполните:

```powershell
python -m scripts.migrate_champions_league_bracket_sync data/predictor.db
```

Скрипт сам создаёт SQLite-бэкап, добавляет nullable-метаданные раундов,
структуры для канонических узлов сетки и долговечный журнал внешнего импорта,
а затем проверяет число исторических записей, `integrity_check` и
`foreign_key_check`. Он не заполняет задним числом раунды, пары, матчи,
прогнозы, результаты или баллы и не пересчитывает исторические данные.

Автоматическая синхронизация доступна только для общего турнира Лиги чемпионов:
там она создаёт будущие пары и распространяет их в связанные конкурсы. Уже
начавшиеся матчи при первом включении задним числом не создаются. Команды
связываются только по точному уникальному имени; неясное соответствие, перенос
после дедлайна или отличающийся результат уже завершённого матча оставляются
как конфликт для ручного разбора. Удалённая импортированная пара помечается в
журнале и автоматически не воскресает. Выключение синхронизации не обрывает
уже начатую обработку одной пары или финала: текущая сущность завершается
целиком, а перед следующей воркер замечает выключение и останавливается.
Источник данных — [football-data.org](https://www.football-data.org/).

Для дополнительной копии production-бэкапов на Windows используются
`scripts/sync_production_backups.ps1` и
`scripts/install_production_backup_task.ps1`. Задача запускается ежедневно в
08:30 по локальному времени, догружает пропущенные копии через SSH, проверяет их
SHA-256 и хранит 14 дней в `%USERPROFILE%\telegram-predictor-bot-backups`.

Если задан `HEALTHCHECK_CHAT_ID`, бот один раз после запуска отправляет в этот
Telegram-чат сообщение о работе Клевера. Без chat ID сообщение отключено.
